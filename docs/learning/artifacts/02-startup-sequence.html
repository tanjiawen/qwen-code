🚀 千问 Code — 启动流程时序图

从 qwen 命令到 TUI 渲染的完整启动链路 · 点击步骤展开详情

💡 整个启动过程分为 4 个阶段：A. Bin Wrapper（进程启动）→ B. CLI 路由（命令分发）→ C. 初始化（配置/沙箱/Config）→ D. 渲染（TUI 或 Headless）
Phase A — Bin Wrapper (进程启动)
① 用户执行 qwen <5ms
scripts/cli-entry.js
Shell 脚本 shim → 调用 cli-entry.js（#!/usr/bin/env node）

standalone 安装时：~/.local/bin/qwen → ~/.local/lib/qwen-code/bin/qwen → 选择捆绑 Node → 执行 cli-entry.js

npm 全局安装时：直接执行 node_modules/.bin/qwen → cli-entry.js

② 路由判断 + 进程重启 ~10ms
scripts/cli-entry.js → isInProcessFastPath()
快速路径（serve/mcp/help/version）直接 in-process 执行；其他命令 spawnSync 重启并加 --expose-gc

• 快速路径：await import(cli.js) 同进程执行，避免 spawn 开销

• 默认路径：spawnSync(node, ['--expose-gc', cli.js, ...args])

• --expose-gc 使 global.gc() 可用，供内存压力监控使用

• 设置 QWEN_CODE_CLI 环境变量（子进程调用自身时定位正确 build）

Phase B — CLI 路由 (命令分发)
③ runCliEntryPoint() ~5ms
packages/cli/index.ts → packages/cli/src/cli.ts
注册 uncaughtException 处理器，调用 runCliEntry()

• 初始化 startup profiler 和 CPU profiler

• resolveBootstrapRoute(argv) 判断路由：serve | mcp | help | version | default

• 非 default 路由直接处理并返回（不加载完整 Config）

④ import('./gemini.js') → main() ~200ms
packages/cli/src/gemini.tsx (1330行)
默认路由：动态导入 gemini.tsx 并调用 main()，进入完整启动序列

动态 import 确保 serve/mcp 快速路径不加载 React/Ink 等重依赖

Phase C — 初始化 (配置/沙箱/Config)
⑤ parseArguments() ~20ms
packages/cli/src/config/config.ts
yargs 解析命令行参数：--model, --prompt, --sandbox, --resume, --output-format 等

关键参数：-p/--prompt（非交互）、-m/--model、-c/--continue、-r/--resume、--safe-mode、--worktree

⑥ loadSettings() ~10ms
packages/cli/src/config/settings.ts
加载 ~/.qwen/settings.json + 项目级 .qwen/settings.json，合并为 merged 对象

• 层级：全局 → 项目 → 环境变量 → CLI 参数

• 包含：model、theme、tools、security、advanced、ui 等配置段

• 损坏检测：JSON 解析失败时自动重置并备份

⑦ 沙箱 / 子进程重启 ~500ms
packages/cli/src/utils/sandbox.ts, relaunch.ts
如启用沙箱（docker/podman/seatbelt），在沙箱内重启；否则以子进程重启（配置内存上限）

• loadSandboxConfig() 判断沙箱类型

• relaunchAppInChildProcess(memoryArgs) — 设置 --max-old-space-size（总内存50%）

• 重启后 process.env.SANDBOX 已设置，跳过此步

⑧ loadCliConfig() ~100ms
packages/cli/src/config/config.ts → packages/core/src/config/config.ts
构建 Config 对象 — 整个系统的配置中心，持有所有运行时状态

Config 持有：model 配置、MCP servers、tools registry、hooks、extensions、session ID、approval mode、memory manager 等

• config.initialize() 触发 MCP 发现、工具注册

• config.waitForMcpReady() 等待 MCP 服务器就绪

⑨ initializeApp() async
packages/cli/src/core/initializer.ts
初始化 MCP 连接、扩展加载、hooks 注册、IDE 连接（可延迟）

• MCP 服务器异步连接（progressive availability）

• Extension 文件监听启动

• Settings 热重载监听启动

• LSP 配置监听（如启用）

Phase D — 渲染 (TUI / Headless)
🔀 分支点：config.isInteractive()
交互模式 (TTY)

startInteractiveUI() → React/Ink 渲染 AppContainer

• setRawMode(true) 接管键盘

• Kitty 协议检测

• 主题自动检测 (OSC 11)

• 信号处理器 (Ctrl+C 双击退出)

非交互模式 (-p / stdin)

runNonInteractive() → 直接执行 prompt → 输出结果 → exit

• 读取 stdin 管道输入

• validateNonInteractiveAuth()

• 支持 text/json/stream-json 输出

• 完成后 runExitCleanup() + process.exit()

📌 性能关键点：快速路径（serve/mcp/help）跳过 Phase C/D 全部，仅需 ~15ms。交互模式完整启动约 800ms-1.5s（取决于 MCP 服务器数量）。startup profiler 可通过 QWEN_CODE_PROFILE_STARTUP=1 启用。
