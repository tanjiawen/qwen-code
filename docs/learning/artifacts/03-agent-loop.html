🔁 递归续写机制
yield* this.sendMessageStream(...) — 三种触发场景

1. Stop Hook 阻断：模型想停止，但 Stop hook 返回 blocking → 注入 continuation reason → 递归继续

2. nextSpeaker = model：模型输出被截断（max_tokens）→ 自动发送 "Please continue." → 递归

3. Steer Input：用户在模型运行时追加了新消息 → 合并到下一轮 → 递归

⚠️ 每次递归 turns 预算 -1，MAX_TURNS 防止无限循环

🛡️ 安全机制
LoopDetectionService
检测连续相同工具调用、内容重复、读写交替等死循环模式。Always-on 安全检查不可跳过。
MAX_TURNS 预算
每次 sendMessageStream 递归消耗 1 turn。耗尽后强制停止，防止无限递归。
MaxSessionTurns
全局会话轮次上限。超过后 yield MaxSessionTurns 事件终止会话。
SessionTokenLimit
prompt token 超过 sessionTokenLimit 时终止，防止上下文溢出。
📌 核心设计思想：Agent 循环不是传统的 while(true) 循环，而是基于 AsyncGenerator + 递归 的事件流模型。UI 层通过 for await 消费事件，工具执行在 UI 层完成后以新的 sendMessageStream(ToolResult) 调用回传，形成"乒乓"式交互。
