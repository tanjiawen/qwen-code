📤 结果回传 LLM
core/src/core/client.ts → geminiChat.ts
UI 层调用 client.sendMessageStream(toolResultParts, type=ToolResult) 回传
  • SendMessageType.ToolResult 标识这是工具结果回传
  • functionResponse parts 必须紧跟 functionCall（API 约束）
  • Memory 注入点：tool result 时消费预取的 recall 结果
  • Microcompaction：size-only 检查（不触发 idle 清理）
  • 循环继续：LLM 可能再次发出 tool calls → 回到步骤 1
🔑 三种审批模式 (ApprovalMode)
📋
Plan
只读模式。所有写操作（edit/write/shell）被阻止，只能读取和搜索。需要 exitPlanMode 工具退出。
⚖️
Default
读操作自动批准，写操作需要用户确认。shell 命令根据只读性判断（isShellCommandReadOnly）。
🚀
YOLO
所有操作自动批准，无需确认。适用于沙箱环境或高度信任场景。Headless 模式会输出安全警告。

📌 设计亮点：工具执行管线将"决策"（权限）和"执行"（execute）分离。PreToolUse hook 提供了 AOP 式的切面能力——外部脚本可以在不修改核心代码的情况下拦截、修改、审计任何工具调用。这是千问 Code 可扩展性的基石。
