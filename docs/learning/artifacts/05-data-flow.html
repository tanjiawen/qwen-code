🧠 Memory 数据流
写入路径:
  模型调用 write_file → ~/.qwen/memories/*.md (user) 或 project memory
  触发: 模型主动 / 用户 "记住这个" / auto-skill 提取

读取路径 (recall):
  用户发消息 ──→ MemoryManager.recall() (异步预取)
                      │
                      ├── 搜索 MEMORY.md 索引
                      ├── 语义匹配相关文件
                      └── 构建 system-reminder 注入
                      │
                      ▼
  注入时机:
  ├── UserQuery → systemReminders.unshift(memory.prompt)
  └── ToolResult → requestToSend.push(memory.prompt)

Auto-Skill:
  会话结束 → 检测重复模式 → 提取为 skill → 写入 ~/.qwen/skills/
🔌 MCP 数据流
配置: settings.json.mcpServers / .qwen/settings.json / mcp.json

启动:
  config.initialize()
    → discoverAllMcpToolsIncremental()
      → 对每个 server: spawn 子进程 / HTTP 连接
        → listTools() → 注册到 ToolRegistry
        → listResources() → 可通过 read_mcp_resource 访问

运行时:
  LLM 调用 MCP 工具 → coreToolScheduler → McpTool.execute()
    → JSON-RPC callTool → MCP server → 返回结果

热重载:
  SettingsWatcher 检测 settings.json 变化
    → registerMcpHotReload() → reconnect / disconnect / restart
📦 核心数据对象
⚙️ Config
全局配置中心，贯穿整个生命周期
  • packages/core/src/config/config.ts
  • 读 getModel(), getApprovalMode(), getToolRegistry()
  • 写 initialize(), shutdown(), setTools()
  • 异步 waitForMcpReady(), refreshAuth()
💬 Content[] (对话历史)
GeminiChat 维护的消息数组
  • packages/core/src/core/geminiChat.ts
  • 结构: { role: 'user'|'model', parts: Part[] }
  • Part 类型: text, functionCall, functionResponse, inlineData
  • 写 addHistory(), 压缩时替换
  • 读 getHistory(), peekLastHistoryEntry()
🔧 ToolRegistry
工具注册表：内置 + MCP + Deferred
  • packages/core/src/tools/tool-registry.ts
  • 内置工具: 静态注册（read_file, edit, shell...）
  • MCP 工具: config.initialize() 时动态注册
  • Deferred 工具: tool_search 按需加载 schema
  • 读 getTools(), getToolDeclarations()
📝 System Prompt

🔄 Context 压缩生命周期
Token 预算模型:

  contextWindowSize (如 128K)
  ├── soft threshold (autoCompactThreshold, 如 80%) → 触发自动压缩
  ├── hard threshold (window - HARD_BUFFER) → 强制压缩 (hard-tier rescue)
  └── output clamp → maxOutputTokens = min(ceiling, window - promptTokens)

压缩触发:
  每次 sendMessageStream 前:
    estimatePromptTokens() → 与阈值比较
      ├── < soft  → NOOP
      ├── ≥ soft → ChatCompressionService.compress() (LLM 摘要)
      └── ≥ hard → 强制 compress (force=true)

微压缩 (Microcompaction):
  独立于主压缩，清理:
  ├── idle 超时工具结果 (thinking blocks)
  ├── 累积大小超限的旧结果
  └── 在 UserQuery / Hook / ToolResult 时触发
📌 架构核心思想：千问 Code 的数据流遵循"Config 中心辐射"模式——所有配置从 Config 对象辐射到各子系统。运行时数据（对话历史、工具结果）在 GeminiChat 内闭环，通过 AsyncGenerator 事件流向上层暴露。Memory 和 MCP 是两条独立的异步数据管道，在特定时机（UserQuery / ToolResult）汇入主流程。
