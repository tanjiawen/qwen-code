# 综合提炼：Agent Harness 研讨会的跨项目共性与 qwen-code 启示

> 基于 7 位嘉宾的深度研究（01-07），提炼跨项目的共性设计原则，
> 映射到 qwen-code 的现状和可改进方向。

---

## 一、七个项目的共同信念

尽管方向各异（运行时、综述、技能进化、上下文管理、沙箱运维、知识图谱、数据生产），
7 位嘉宾共享一个根本判断：

> **Agent 的可靠性不来自更强的模型，而来自模型之外的那一圈工程基础设施。**

周宸宇的综述把它理论化为"外部化范式"，任旭滨在 Nanobot 里把它工程化为
"small core + pluggable everything"，吴晓均在 Bayesian-Agent 里把它量化为
"后验信念驱动的技能演化"，王天富在 MindOS 里把它人本化为"人机共进的共享心智"。

**同一个信念，七个切面。**

---

## 二、五条跨项目共性设计原则

### 原则 1：运行时核心要小，外围要可插拔

| 项目       | 体现                                                                      |
| ---------- | ------------------------------------------------------------------------- |
| Nanobot    | ~4000 行核心循环，Channel/Provider/Tool/Memory 全部注册制                 |
| DataFlow   | Operator 是原子单元，Pipeline 是编排，互不耦合                            |
| OpenKruise | CRD 声明式定义沙箱，Controller 只做 reconcile                             |
| qwen-code  | 核心循环（query → model → tool → respond）相对精简，Tool/Skill/MCP 注册制 |

**共性**：把"不变的循环"和"可变的能力"分开。循环越小越稳定，能力越多越好，
但两者不能耦合。

### 原则 2：知识要外部化、可审计、可演化

| 项目               | 外部化什么                     | 怎么审计                 | 怎么演化                    |
| ------------------ | ------------------------------ | ------------------------ | --------------------------- |
| Bayesian-Agent     | Skill 可靠性 → 后验信念        | Beta 参数 + 失败模式计数 | patch/split/compress/retire |
| MindOS             | 人机协作经验 → Markdown 知识库 | Git 版本控制 + 审计日志  | Dreaming 后台整合           |
| DataFlow-Skills    | 操作规范 → MANDATORY 规则      | 运行前验证（compile）    | 人工迭代                    |
| qwen-code SKILL.md | 过程知识 → 步骤 + 约束         | 无（纯文本）             | 无（人工编辑）              |

**共性**：隐性知识必须变成显性制品（文件、数据库、信念状态），
否则不可审计、不可改进。qwen-code 的 SKILL.md 已经做了外部化，
但缺少审计和演化机制。

### 原则 3：验证必须来自外部，不能靠模型自评

| 项目           | 验证机制                                                    |
| -------------- | ----------------------------------------------------------- |
| Bayesian-Agent | 外部 benchmark grader 判定成功/失败，模型永远看不到概率数字 |
| DataFlow       | 字段契约 + 运行前 compile 验证                              |
| OpenKruise     | CRD status 由 Controller 写入，Agent 不能自报状态           |
| qwen-code Hook | typecheck + 测试标记（exit 2 硬拦截）                       |

**共性**：Agent 说"我做完了"不算数，必须有独立于 Agent 的验证通道。
qwen-code 的 truth-guard Hook 已经实现了这一点（机械层面），
但语义层面的验证（测试质量、逻辑正确性）仍是开放问题。

### 原则 4：人机关系不是"人指挥 AI"，而是"共同进化"

| 项目               | 人从 AI 获得什么                     | AI 从人获得什么              |
| ------------------ | ------------------------------------ | ---------------------------- |
| MindOS             | 思考原料、知识缺口发现、经验模式沉淀 | 偏好、判断、审查反馈         |
| Bayesian-Agent     | 可解释的技能可靠性报告               | 验证轨迹、失败模式标注       |
| qwen-code 记忆系统 | 费曼式讲解、完整步骤、坦诚的边界说明 | 沟通偏好、设计哲学、项目进度 |

**共性**：单向的"人→AI 指令"模式不可持续。
好的 Harness 让每次交互都成为双方下一次协作的基础。
qwen-code 的记忆系统（memories/）已经朝这个方向走了，
但还没有 MindOS 那样的结构化审计和健康度管理。

### 原则 5：安全是功能，不是中间件

| 项目       | 安全怎么做                                                            |
| ---------- | --------------------------------------------------------------------- |
| Nanobot    | restricted/full 两种访问模式，ContextVar per-turn 隔离                |
| OpenKruise | SecurityProfile（L7 策略）+ TrafficPolicy（L3/L4 隔离），Key 不进沙箱 |
| qwen-code  | 审批模式（yolo/auto/manual）+ Hook 拦截 + 沙箱                        |

**共性**：安全不能是事后加的 `if` 判断，必须是架构级的一等公民。
OpenKruise 的"API Key 永远不进沙箱"是一个值得学习的设计——
不是"进去了但加密"，而是"根本不让它进去"。

## 三、qwen-code 在外部化框架中的成熟度评估

基于周宸宇综述的四层框架，对照所有研究的发现：

| 外部化维度                  | 成熟度 | 对标最佳实践                          | 差距                          |
| --------------------------- | ------ | ------------------------------------- | ----------------------------- |
| **Memory — 工作上下文**     | ★★★★   | Nanobot 的上下文构建链                | 基本持平                      |
| **Memory — 个性化记忆**     | ★★★★   | MindOS 的知识库                       | 缺审计日志和健康度管理        |
| **Memory — 情景经验**       | ★★     | MindOS 的 Git 版本控制                | 跨会话轨迹无结构化存储        |
| **Skills — 规约与发现**     | ★★★★   | DataFlow-Skills 的 MANDATORY 规则     | 基本持平                      |
| **Skills — 演化**           | ★      | Bayesian-Agent 的后验信念             | 完全缺失，规则只增不减        |
| **Protocols — Agent-Tool**  | ★★★★   | MCP 标准                              | 基本持平                      |
| **Protocols — Agent-Agent** | ★★★    | Nanobot 的多通道消息总线              | 子 Agent 间无结构化协议       |
| **Harness — 控制流**        | ★★★★   | Nanobot 的 AgentLoop/AgentRunner 分离 | 基本持平                      |
| **Harness — 沙箱**          | ★★★    | OpenKruise 的 CRD 声明式沙箱          | Docker 沙箱功能够用但不可编排 |
| **Harness — 验证**          | ★★★    | Bayesian-Agent 的外部验证器           | 有 Hook 硬拦截，缺语义验证    |
| **Harness — 可观测性**      | ★★     | OpenKruise 的结构化轨迹               | 有基本日志，缺结构化追踪      |
| **Harness — 自演化**        | ★      | 综述论文的首要未来方向                | 完全静态，不从经验中学习      |

## 四、按优先级排序的改进方向

### 短期可做（不改核心代码）

| #   | 改进                                  | 来源                   | 成本                  |
| --- | ------------------------------------- | ---------------------- | --------------------- |
| 1   | SKILL.md 约束添加置信度注释           | Bayesian-Agent Phase 0 | 零代码                |
| 2   | 记忆系统添加审计日志                  | MindOS                 | 低（Hook 记录写操作） |
| 3   | 工具定义稳定排序（利于 prompt cache） | Nanobot                | 低                    |

### 中期可做（小规模代码改动）

| #   | 改进                                 | 来源                   | 成本       |
| --- | ------------------------------------ | ---------------------- | ---------- |
| 4   | Beta-Bernoulli 技能信念追踪          | Bayesian-Agent Phase 1 | ~100 行 TS |
| 5   | 记忆健康度评分（过期检测、冲突检测） | MindOS                 | ~200 行    |
| 6   | 结构化执行轨迹存储                   | 综述论文               | ~300 行    |

### 长期方向（架构级改动）

| #   | 改进                                   | 来源                  | 成本 |
| --- | -------------------------------------- | --------------------- | ---- |
| 7   | 技能自动蒸馏（从轨迹中提取新 Skill）   | 综述 + Bayesian-Agent | 高   |
| 8   | 跨会话情景记忆（可检索的先例库）       | MindOS + 综述         | 高   |
| 9   | Harness 自演化（配置从经验中自动改进） | 综述首要未来方向      | 很高 |

## 五、一句话总结

这 7 个项目从不同角度回答了同一个问题：**怎么让 Agent 从"能跑 demo"变成"能上生产"？**
答案不是更大的模型，而是更好的 Harness——更小的核心、更外部化的知识、
更独立的验证、更双向的人机关系、更内建的安全。

qwen-code 在控制流、工具协议、技能编码上已经做得不错；
最大的提升空间在**技能演化**（从硬规则到软信念）和**情景记忆**（从扁平文件到可检索先例）。
这两个方向恰好是 Bayesian-Agent 和 MindOS 分别解决的。
